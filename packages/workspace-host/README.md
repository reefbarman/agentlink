# @agentlink/workspace-host

`@agentlink/workspace-host` composes the portable AgentLink engine into one local-project coding session without depending on VS Code, Electron, a browser gateway, or terminal presentation.

The host owns canonical project identity, durable sessions, provider composition, bounded model requests, project-relative file tools, and durable reviewed-write interactions. Commands, MCP, delegation, and optional language services land in later standalone CLI slices.

`createWorkspaceFileTools(...)` composes bounded `read_file` content/context, list, and search tools with baseline-hash single-file writes and canonical patches. File scopes are resolved per principal, session, and turn; pending approvals bind the exact canonical input, project, scope, baseline, proposed content, and policy revision. Optional session grants receive the complete prepared proposal so callers can bind them to the tool and verified content-hash chain. Successful writes re-read disk content and return a verified final hash with exact durability evidence.

`promptIdentity: { role }` makes system prompts start with `You are AgentLink, <role>.`, the identity the Meridian companion plugin recognises. Without it, the existing standalone identity is unchanged.

`sharedPromptGuidance: true` leads the prompt with VS Code's guidance from `@agentlink/core/system-prompt`, for the tools each session actually registers (file edits, `ask_user`, `todo_write`, `set_task_status`, session recall). The host's own capability sentences and instructions follow it. Off by default. A general assistant passes `sharedPromptGuidance: { codingAssistant: false }` to leave out VS Code's "primarily a coding assistant" rule. Combine it with `meridianSessionAffinity: true` on an OpenAI-compatible provider to send each session ID as `x-session-affinity`.

`execute_command` follows VS Code's input and result (`timeout` in seconds, `env`, `output_grep`/`output_head`/`output_tail`/`output_offset`, `command_id`, `exit_code`, filtered `output` and line counts). `commands.environmentOverrides: "add_only"` refuses an `env` variable the host environment already sets; the default `allow` lets a call set any variable except `PWD`. `get_terminal_output` (by `command_id`, with the output filters, `wait_seconds` and `kill`) and `close_terminals` (running commands, or the command IDs in `names`) replace `get_command_output`, `list_commands` and `stop_command`. `commands.readOnlyCommands({ sessionId, turnId })` returns a read-only policy for a session: commands VS Code's read-only check (`@agentlink/core/command-classifier`) clears run without asking, `background`/`env` are refused, and anything else is refused (`"refuse"`, `readonly_policy_rejected`) or gets an approval card that ignores session grants (`"prompt"`). With modes on, Ask mode (VS Code's `read-only-command` group without `command`) uses `"prompt"` unless the callback returns a policy.

`modes: { enabled: true }` gives foreground sessions VS Code's agent modes from `@agentlink/core/agent-modes`: Code, Architect, Ask, Debug, Review and the project's custom modes from `modes.json` (Orchestrate is not offered). `listModes()` lists them, `createSession({ mode })` and `setSessionMode(sessionId, slug)` choose one, and the slug is stored on the session record and returned by `listSessions()`. Every tool stays advertised; one outside the mode's groups returns VS Code's `tool_not_in_mode` result without running or asking for approval. The mode's instructions (gated to the session's tools, with its `rules-<mode>` content when `agentInstructions` is on) are prepended to the next message in a `<current_mode>` block when the mode changed or condensing dropped it; `stripModeInstructionBlock` removes it for display. Background children keep their parent's mode.

`modes.confirmSwitch(request)` (with `sessionInteractions`) adds VS Code's `switch_mode` and `ask_user` `modeSwitch` for foreground sessions: the callback gets `{ sessionId, mode, modeName, reason }` and returns `{ approved, rejectionReason?, followUp? }`; an `ask_user` answer mapped to a mode switches without calling it. An approved switch ends the turn even with a queued message (later calls get VS Code's `mode_switch` skip; the message waits for the continuation), is stored once the session is idle, calls `modes.onSessionModeChanged(sessionId, mode)`, and `runTurn`/`resumeInteraction` continue in the new mode with VS Code's resume message (`buildModeSwitchResumePrompt`, up to `MAX_MODE_SWITCH_RESUMES`) before returning. A host tool can end the turn with `endTurn: { skippedResult }` to choose what the skipped calls are told.

`executionBackend` moves project file access and processes off the host machine. It covers `execute_command`, file reads, listing, writes, `find_and_replace`, `search_files` (including the packaged ripgrep process), and the Git status probe in `read_file`'s context view. The host still prepares, authorises, records, and redacts every operation, and keeps the baseline-hash, write-lock, and post-write verification logic: the backend's `fileSystem` performs primitive operations only, and `launchProcess` receives a single `WorkspaceProcessLaunchRequest` and reports output, exit, and process-group signals. Paths stay in the host's canonical absolute namespace, so a remote backend must map them onto its own storage consistently, including `realpath` results. With commands enabled, an injected backend requires an explicit `commands.resolveEnvironment`; search and git probes only ever receive a fixed minimal `PATH`. Project identity and ownership, language services, stdio MCP, and instruction/artifact catalogs still run in the host process, so this seam alone does not make a host sandboxed, and command approvals still report `unsandboxed: true`.

`acquireWorkspaceOwnership(identity, dataRoot)` uses a private local `workspace-owners.json` registry to reserve exclusive CLI writer ownership for a canonical project root, including overlapping roots. It returns an async, idempotent release handle. Callers must pass an explicit absolute data root and release ownership when the session ends.
