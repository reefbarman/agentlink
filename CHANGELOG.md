# Changelog

## Unreleased

## 1.65.0

- Reloading a session now restores the detected question card when the last turn ended waiting for the user, and dismissed cards stay dismissed when the same session is reloaded.opt.

## 1.64.0

- When the agent finishes a turn waiting for the user and ends with a direct yes/no question, the chat now shows a Yes/No choice card; "A or B" questions are excluded.

## 1.63.1

- Question cards in the browser gateway now disappear once the question has been answered on another surface such as VS Code, instead of staying visible until the next question.
- Yes/No choice card detection now uses only the turn's final message (summary or last text block) and ignores quoted question marks, avoiding bogus cards from mid-turn narration.

## 1.63.0

- CLI and Assistant turns now preserve request-scoped model state and controls through the shared SDK engine, including Codex conversation recovery state, temperature, retry/output controls and provider-attempt callbacks. These options were composed by workspace-host but dropped before the turn kernel, so Codex conversation-level fallback could not carry across standalone turns or resumed approvals. VS Code behavior is unchanged.
- The CLI and Desktop Ask Agent now keep MCP OAuth records in one shared standalone Keychain item instead of one item per surface. Their principals, servers, OAuth client registrations, and callback URLs remain logically separate inside the vault. Each surface lazily imports its existing item and keeps it as a compatibility replica for older preview builds, including updates and deletions, so existing users may see one final migration prompt while new installations use only the shared item. VS Code's mature MCP OAuth storage is unchanged.
- OpenAI-compatible provider startup now reads one Keychain item instead of two. The second item only held a non-secret `managed`/`deleted` migration marker, but macOS treated it like another password and asked for a second **Always Allow**. New builds read markers from a private local state file under `~/.agentlink/credential-state/openai-compatible`; the old Keychain marker remains a write-only compatibility mirror for older Desktop or VS Code versions and is read only when both the API key and local marker are absent. This preserves deletion and legacy-migration behavior without adding a prompt to the normal existing-key path.
- The new macOS credentials helper now queues Keychain requests across startup consumers, AgentLink surfaces and VS Code windows. On first use, concurrent Codex, provider and MCP credential reads could all reach macOS before the first **Always Allow** updated the old item's access list, leaving a stack of prompts that appeared not to go away. Helper requests now wait behind one atomically published cross-process lock for up to five minutes while a prompt is open. If a host crashes while holding the queue, later requests fail closed rather than risk starting a second prompt.
- macOS: signed builds of VS Code, the CLI and Desktop now share credentials through **AgentLink Credentials**, a small signed helper, so one **Always Allow** for a particular Keychain item covers every surface. macOS resets a Keychain item's trusted developers on every write, so a Codex token refresh in the CLI or Desktop (signed by AgentLink) locked out VS Code (signed by Microsoft) and the reverse. Each surface ships its own copy, named "AgentLink Credentials (VS Code)", "(CLI)" or "(Desktop)", so the prompt says which surface is asking, and items are labelled with what they hold, such as "AgentLink: Codex sign-in (shared by VS Code, CLI and Desktop)". Expect one last prompt per credential when a helper first uses it. The helper only serves VS Code and AgentLink's signed CLI and Desktop and only gets, stores and deletes AgentLink's items. Builds without it (unsigned previews, other platforms, source runs) use the Keychain directly, as before. The CLI runtime is renamed from `node` to `AgentLink CLI`, keeping its signing identifier, so unsigned preview installs need one manual update before self-update recognises the new layout.
- AgentLink no longer rewrites a shared Keychain credential when the value has not changed. On macOS every rewrite resets the item's list of trusted signing teams to the writer's, so a needless save by the CLI or Desktop made VS Code ("Code Helper (Plugin)") ask for Keychain access again even after "Always Allow". Real changes, such as a refreshed sign-in token, can still cause one prompt on the other surfaces until shared credentials move to a single signed helper.
- The CLI no longer exits when a background MCP reconnect fails. A scheduled retry for a server such as one waiting for sign-in could be refused by the CLI's connection policy, and nothing handled that rejection, so Node ended the process with "MCP server '...' connection denied by host policy". The failure is now logged like the hub's other background reconnects. VS Code uses the same hub and only gains the log line.

## 1.62.1

- CLI and Assistant MCP tools whose input schemas declare JSON Schema draft-07 (the default output of zod-to-json-schema, used by many servers) no longer break the session. The strict host-tool schema check could not resolve the draft-07 `$schema` header, so one such server made `/condense` and automatic condensing fail with "Host tool ... input schema is invalid". workspace-host now drops the header, as VS Code and the browser Ask Agent already do, and leaves out any single tool whose schema still cannot be compiled, which stays reachable through `find_mcp_tools` and `call_mcp_tool`.
- `/condense threshold` in the CLI now shows a threshold changed in VS Code straight away, instead of the previous value until the next background refresh.
- The CLI composer no longer keeps a raw carriage return when Enter arrives in the same input chunk as text (a fast or unbracketed paste). It becomes a newline, instead of an invisible character shown as "�" and sent to the model.

## 1.62.0

- The VS Code agent can now look up earlier sessions in the same project with `search_workspace_sessions` and `read_workspace_session_excerpt`, so it can check whether something was worked on before and read the original discussion. Search uses a local lexical index of saved history (no embeddings or external calls), re-reads each matching session before returning excerpts, and reports when indexing is incomplete. Background agents, bounded profiles, other projects and skills that don't name the tools don't get access, and current-session recall is unchanged. SDK: `@agentlink/core/workspace-session-history` provides the shared service and tool handlers for hosts that supply their own session source and index.

## 1.61.0

- The ask_user question composer gains a Chat input button that sets the question aside so slash commands like /mcp can run while it stays pending, with a Back to question button to restore it.

## 1.60.0

- `web_fetch` with Codex no longer stops partway through longer pages when you ask for a short preview. The provider ignores the requested continuation line and sizes each page by the requested output budget, which AgentLink took from `max_length`, so a 3,000-character preview fetched only about 16K characters and every continuation repeated that same page ("Provider pagination did not advance"). AgentLink now sizes the provider window from the retention budget and still trims the inline preview locally.
- Sandboxed commands with network access on macOS can now reach the system certificate trust service, so `gh`, `gcloud`, `terraform`, `kubectl` and other Go CLIs verify TLS inside the sandbox instead of failing with `x509: OSStatus -26276` and needing a reviewed retry outside it. This matches Codex CLI's sandbox policy. Commands without network access keep the service blocked, and certificate verification is unchanged.

## 1.59.1

- CLI and Assistant condensing now works with Codex models. The summariser asks for temperature 0, which VS Code's providers drop when a model does not support it but the SDK's Codex backend rejected, so `/condense` and automatic condensing failed with "Responses backend does not support temperature". The SDK condenser now leaves temperature out unless the model supports it. VS Code behaviour is unchanged.
- When a CLI turn fails, the error now says why (for example the provider's message) instead of only "Turn execution failed". The cause is redacted the same way as the Assistant's job and Inbox failure details, which now share the code through workspace-host's `describeTurnFailure`.
- The CLI's activity shelf no longer counts the Context row as live activity, so an idle session no longer shows "1 live", and a failed condense is cleared from the Context row when the next turn starts.
- Escape in the CLI no longer leaves the composer unable to take input. Ink's focus manager cleared focus on Escape; focus now returns to the composer.
- Approve for Me now remembers public sites that Guardian (or the Jev first pass) approves at low or medium risk for the rest of the chat session, so later sandboxed commands reaching the same exact destination no longer wait for another review. The saved rule is an ordinary session network rule: it appears with your other session rules, can be removed, and disappears with the session. Network Prompt/Forbidden rules, private-address blocking and human fallback for risky or unavailable reviews are unchanged.
- `web_search`, `web_fetch` and `execute_command` descriptions now steer web research and page reading to the native web tools instead of `curl`, `wget` or ad hoc fetch scripts, which need a network approval for every new site when sandboxed.

## 1.59.0

- The Assistant's Remembered lines above the composer get a restyled look with a clearer Undo button, and the activity shelf background now follows the theme.
- The standalone CLI gains /condense and /condense threshold, sharing per-model condense thresholds with VS Code, backed by new SDK condense APIs (manual trigger, sessions.condense, host.condenseSession, condense.thresholds).

## 1.58.0

- The standalone CLI and Assistant now also condense in the middle of a turn, before each model call after the first, as VS Code does. A single turn whose tool results outgrow the model is summarised (including that turn's own work so far) and keeps going, instead of failing. A summary made while a tool is waiting for approval survives the pause.
- The CLI and Assistant no longer condense at about a quarter of the model's window. Their check before sending a request used to count one byte as one token; it now uses the condenser's estimate of about four characters a token, so condensing happens near VS Code's point. The fixed request-size ceiling is unchanged, and `inputSafetyTokens` is the margin for estimate error.
- The CLI now has `/condense`, which summarises the current session's history on request, as VS Code's `/condense` does. It runs only while the session is idle, Ctrl+C stops it, and the Context row shows the estimated request size before and after.
- `/condense threshold [0.1-1|default]` in the CLI shows or sets when the current model condenses automatically. It uses the same per-model `modelCondenseThresholds` in `~/.agentlink/session-preferences.json` as VS Code's condense threshold control, so a change in either applies to both, and a running CLI picks up VS Code's changes within a few seconds. As in VS Code, an idle session already over the new point is condensed straight away.
- SDK: `engine.sessions.condense()` summarises an idle session with the configured `contextCondenser` (trigger `"manual"`), workspace-host adds `host.condenseSession()`, and `createSummarizingContextCondenser({ thresholds })` and workspace-host `condense: { thresholds }` accept a function read on every check. VS Code behaviour is unchanged.

## 1.57.0

- The standalone CLI and Assistant now condense long chats with VS Code's summariser and default thresholds instead of failing once the conversation outgrows the model. Before a turn near the limit, earlier history is summarised and kept in the transcript; a request rejected as too long (by the provider or the host's own size check) is condensed and retried once. The CLI shows it in the activity shelf's Context row, and stored summaries are hidden from restored transcripts. SDK engines opt in with `contextCondenser: createSummarizingContextCondenser()` (or workspace-host `condense: { enabled: true }`, which requires `sessionRecall`). Condensing in the middle of a turn, `/condense` and threshold settings are not in the CLI yet. VS Code behaviour is unchanged.

VS Code's context-condense summariser and `todo_write` tool moved into `@agentlink/core` (`context-condense`, `todo-tool`) so other agents can use them; VS Code behaviour is unchanged. Condensing long CLI and Assistant chats comes next.

## 1.52.0

## 1.51.0

Pages are read directly from your machine (public sites only; private, local and IP-address hosts are refused, and fetching refuses to run around a configured proxy). The Assistant now uses the same tool implementation, with its project network presets unchanged.

## 1.50.2

- `find_and_replace` (and `rename_symbol`) no longer report success when the change never reached disk. When VS Code held the file under a differently cased path, for example on an SMB share mounted under `/Volumes`, the replacement stayed unsaved in the editor while the tool returned `applied`, and the next search then missed text that was still on disk. Saves now follow the documents the edit actually changed, and the tool reports a save failure unless the file on disk matches.
- `apply_diff` and `write_file` now accept an editor whose path differs from the requested path only in letter case. Previously they refused with "Review editor does not match the target file" on case-insensitive volumes such as SMB shares.
- Settings and `mise` config reads and searches now also redact environment-style names ending in `_KEY`, `_SECRET` or `_PASSWORD` (for example `OPENROUTER_DEV_KEY` or `GRAM_ENCRYPTION_KEY`), and any value with a well-known provider key prefix such as `sk-` or `ghp_`. Previously these were returned in full.

## 1.44.3

- MCP servers whose tool definitions use `true` or `false` as a property schema (valid JSON Schema, and common from Go servers) now load their tools. Previously the MCP SDK rejected the whole tool list, so the server showed zero tools, or kept reconnecting with an "Invalid input" error. Tools that still can't be read are skipped one at a time and logged. If a server's tool list can't be read at all, automatic retries now pause instead of looping.

## 1.44.2

- An MCP server whose tool list fails right after connecting (for example a 401 from `tools/list`) no longer shows as connected with zero tools. It now goes through the usual sign-in and retry handling, and if that fails it shows as an error with the reason, which `find_mcp_tools` reports. Servers that don't support tools at all still connect normally.

## 1.44.1

- Jev no longer treats ordinary command text as a possible secret. Timestamped file names such as `migrations/20250101120000_add-user-index.sql` and image digests such as `@sha256:…` were redacted, and any command containing your home folder counted as altered because the path is shown as `~`. Either made the review ineligible. In recent Jev traffic, 21 of the 22 commands Jev saw as altered were one of these; the remaining one was over the size limit. Random-looking tokens, keys and passwords are still redacted.
- Long instructions you type now reach Jev in full. Your latest instruction was cut off at 1,200 characters and earlier ones at 2,000, so a long request or a pasted spec made every later review in that session ineligible. Jev now gets the full text of your latest instruction (up to 8,000 characters) and earlier instructions up to 20,000 characters. The main Guardian's evidence is unchanged. In recent traffic this accounted for all 15 reviews that were missing one piece of your input.

## 1.40.0

- AgentLink Assistant installer: turn the optional **Edit task workspaces** (`editor`) and **Research with a browser** (`browser`) features on or off with `install.sh enable|disable editor|browser`, list them with `install.sh capabilities`, and stop the whole installation with `install.sh uninstall` (undo with `resume`). Changes use the release's own hash-checked template and pinned image, drain work and take a backup first, and put the previous configuration back if the Assistant does not start. Uninstall removes only the Assistant's own containers and networks and deletes nothing: configuration, secrets, data and backups stay, and removing them for good is left to you. Browser updates and these commands share a deployment guard, so they never overlap; an interrupted change blocks both until `install.sh recover` puts the saved configuration back. **Setup → Connections** shows each feature's state and the command to run, but cannot change it. Needs a release with `"lifecycleProtocol": 1` in its deployment metadata. Turning a feature on or off retires the last update's rollback point and says so, because rolling that update back afterwards could remove a template the new configuration uses; rollback then refuses with nothing stopped, and going back past it means restoring a backup.
- AgentLink Assistant: use an OpenAI API key instead of ChatGPT, set up in the browser. On a guided installation, **Setup** takes a key for AgentLink's built-in OpenAI provider and, as a separate step, the model for new chats, with no `server.json` change and no restart: chats, tasks, scheduled runs, session runners and task editors use the new key and models on their next request. The key is stored privately by the server, shown only as `sk-…abcd`, and never returned, logged or kept in the browser; a failed save keeps the previous key. Saving sends nothing to OpenAI (API use is billed separately from ChatGPT; the first chat is the first billed request). Removing the key keeps the chosen model, so new chats on it fail clearly rather than quietly using another provider. OpenAI providers in `server.json`, custom endpoints and Claude/Meridian stay operator configuration, and existing installations are unchanged.
- AgentLink Assistant: browser setup and ChatGPT sign-in. A fresh guided installation opens a resumable setup guide in the first paired browser: connect ChatGPT without the terminal (open OpenAI's sign-in, paste back the address it ends on), confirm name, time zone and quiet hours, see optional GitHub/MCP connections, and check models, backups and the backup password. Progress is kept on the server, so any paired device carries on; closing it means "later", and **Setup** in the toolbar reopens it. One sign-in waits at a time, owned by the device that started it; addresses, codes and tokens are never stored in the browser or logged. Existing installations only get the toolbar entry, and servers without a ChatGPT provider are reported as operator-managed.
- AgentLink Assistant installer: a read-only `diagnose` command and stricter preflight. Installation now stops before downloading or changing anything on remote Docker contexts, rootless Docker, non-system Linux sockets, non-Desktop macOS engines, emulated daemons, a busy port 8443 or an unwritable location, and warns about low disk space and unresolved origins. The witness image is pulled with the others before any state exists, partial-install recovery now starts the update supervisor too, and the finishing steps put pairing before model sign-in and report a missing first backup as degraded setup. Release notes now describe managed transactional updates.
- AgentLink Assistant: managed release installations gain Settings update checks, cached release notes, stable/preview preferences, explicit update/rollback confirmation and reconnecting progress. A separate narrow supervisor runs fixed, digest-pinned update jobs and transactionally updates management assets with images using the existing drain, backup, health-check and rollback flow. Configuration and credentials are retained; modified templates and source/legacy deployments fail closed. A rollback checks that the previous update supervisor image is on the machine (pulling it by digest if not) before stopping anything, and refuses if it cannot be had. No unattended application or update notifications are enabled. Images have not been published and real-host upgrade/rollback qualification remains outstanding.

- AgentLink Assistant installation/update foundation: an independent `assistant-v*` release pipeline for prebuilt GHCR images and deployment assets, a guided Linux/macOS installer without a host source build, and explicit-version image updates using the existing backup/health-check/rollback flow. The installer refuses existing deployments and leaves certificate trust, model sign-in and pairing to the owner. Publication and fresh-host qualification are not yet complete.

- AgentLink Assistant: polish the management panels with persistent headers, keyboard focus containment, responsive spacing and consistent controls. Settings groups persona, schedule and storage into readable sections with change-aware saving; Tasks gains search and state filters, Jobs gains search, and Memory has clearer search and empty states. MCP tool permissions now have structured rows instead of an unstyled nested list.

- AgentLink Assistant server: scheduled jobs. A job sends a prompt to a new chat every N minutes (15 or more), daily, or on chosen weekdays at a local time in an IANA time zone, with no browser open, through the owner-only `/api/jobs` routes. Runs never approve anything themselves: one that needs an approval waits up to 12 hours, then is cancelled. Runs missed while the server was down become one catch-up run if recent, a run interrupted by a restart is recorded as interrupted and never re-run, and finished runs appear unread in the project's chat list.
- AgentLink Assistant web app: **Jobs** and **Inbox**. Jobs lists each job's schedule, next run and last outcome, and lets you create, edit, pause, delete and run a job now, with a run history that opens each run's chat. Run chats carry a clock badge, show a running run live, and show its approval card so you can answer it there; Stop in a run's chat stops the run. The Inbox collects finished, failed, blocked and approval-waiting runs with an unread badge, opens the run's chat, and marks entries read. Push notifications are not available yet.
- AgentLink Assistant: a failed or blocked job run now says why. The run keeps the provider's or server's actual error (redacted and shortened), shown in the Jobs history and the Inbox entry instead of only a code such as `turn_execution_failed`, and failed turns are described in the server log. Chat events still carry only the safe public error.
- AgentLink Assistant: create scheduled jobs from a chat. Ask for something on a schedule and the Assistant proposes it with the new `schedule_job` tool; an approval card shows the exact name, project, schedule, first run, approval mode, model and prompt, and nothing is saved until you allow it, even in an autonomous chat. `schedule_job` with a job ID changes a job and `delete_job` deletes one, with the same approval; `list_jobs` reads them. ### Security

- Treat web search results and fetched pages as untrusted model input in both owning runtimes; embedded prompts must not override the user/system request, reveal secrets, or exfiltrate private/workspace data.
- Provider-hosted web requests may incur additional provider charges and send queries or fetched content to the selected provider. MCP requests send them to the configured server; self-hosted SearXNG does not make upstream search engines private.

Native reviewers use a lightweight prompt and focused local read tools without MCP/history/memory, and costly tiers require explicit selection. Review limits are now generous safety ceilings rather than routine stopping points: 50 calls / 25 turns / 15 minutes, 100 / 50 / 30 minutes, or 150 / 75 / 45 minutes with warnings at 80% and a 1.5× emergency backstop. Agent Fleet rows in VS Code and browser remote now include a one-click **Wrap up** steer action alongside custom steer, pause, and stop. Warned native structured reviews that stop without a result now retry one transient empty response, then receive up to three finalization-only attempts with only `set_task_status`; those packaging requests do not consume review work allowances. The structured `terminal_cleanup` response lists inactive terminal IDs/names, excludes busy terminals, shares warning state with related child sessions, and recommends `close_terminals` only when it is available in the current mode. Cleanup inspection cannot change the command result.
- Moved autonomous and derived-session memory to one canonical helper-owned store under `~/.agentlink/`, shared by VS Code and Browser Ask Agent. Browser memory no longer depends on connected VS Code owner descriptors; prior per-profile retrieval stores migrate idempotently with records, revisions, audit history, forgotten/superseded state, and derived summaries preserved for rollback. The machine-local memory mode config is shared across surfaces, and malformed or unreadable config fails closed with bounded diagnostics.

- Made the helper-owned browser relay/data plane the dogfood default through `agentlink.browserGateway.dataPlane`; `shadow` retains dual publication with legacy browser traffic, and `off` preserves complete snapshot/proxy rollback while semantic parity work continues.
- Hide the Agent Fleet panel after every background agent finishes, while keeping paused work visible and adding `/fleet` to reveal completed results again in VS Code or the browser remote.
- `get_background_result` now requires a bounded `wait_seconds` value from 1 to 60. If the interval expires, it returns `status: "still_running"` with current progress, partial output when available, `retryAfterMs`, and explicit guidance to continue independent foreground work rather than block or immediately poll again. User interjections still return early with `status: "wait_interrupted"`, and neither outcome stops the background agent.
- Matched Codex-style sandbox loopback behavior on supported local macOS hosts: baseline commands can connect to loopback services but cannot bind TCP listeners, while a fresh exact-command `allow_local_binding` capability review permits listeners without granting public or private outbound access.
- Coupled Approve for Me to session-scoped writes: enabling it enables session writes, turning session writes back to Prompt disables it, and both remain active across mode switches only while Approve for Me is active. While the complete Approve for Me policy is active, `write_file` and `apply_diff` can write beneath the operating system's canonical temporary roots (including the per-user temp root and `/tmp` aliases on macOS) without a separate outside-workspace approval; protected instructions/memory, `.env*`, credential stores, authenticated CLI configuration, unresolved paths, and symlink escapes remain human-reviewed.

Guardian never persists rules. Under Approve for Me, mode switches normally proceed immediately without Guardian or user approval. ### Fixed

- Moved Browser Ask Agent automatic recall out of system instructions into low-authority, request-local conversation evidence for both Codex and OpenAI-compatible providers. A fixed per-turn insertion anchor avoids moving earlier context during tool loops; explicit delegated instructions and transcript privacy remain unchanged.

- Enabled Codex OAuth conversation cache keys and in-memory turn-scoped sticky routing across VS Code and browser chat paths. Routing state is isolated across conversations, credentials, models, and turns; explicit pre-stream routing-field rejection falls back once without the optimization, with no new response storage or retention request.

- Kept post-condense resume context at a fixed checkpoint position with checkpoint-time user/TODO state. Later messages and TODO updates no longer rewrite or relocate the early provider-history prefix, avoiding unnecessary prompt-cache invalidation while preserving chronological updates.

- Fixed AgentLink Desktop exposing VS Code instance tabs during the Ask-Agent-only MVP, closing its account window before chat finished loading, and identifying its helper runtime with the internal desktop package version. Shared macOS Keychain reads are now cached per host and invalidated through a non-secret revision marker, reducing repeated access prompts while preserving immediate cross-surface account updates.
- Fixed Native Agent command transport corrupting long or separator-heavy approved commands. Native commands now run from verified private artifacts instead of being retyped through the interactive line editor, one-shot SSH remote commands are distinguished from interactive SSH sessions, and safe workspace-root `git init` chains receive protected-metadata native-retry guidance before launch.
- Fixed agent-started terminal commands bringing a background VS Code window to the foreground. Automatic terminal selection now waits until that window regains focus, while explicit terminal-open actions remain immediate.
- Fixed lean background reviews diverging at backend and telemetry boundaries. ACP `review_*` tasks now inherit the same read-only and structured-result defaults as native reviews, handoff telemetry measures the complete shared brief and records the router-resolved tier, scope-less reviews retain coordinator-facing scope attribution, and live `files` targets must exist as files at spawn and again when queued work starts.
- Fixed running `get_terminal_output` activity cards lacking the terminal navigation and intervention controls available on `execute_command`. The card now opens the observed terminal, can return retained output and control to the agent, and cancels only the output wait unless `kill: true` explicitly requests Ctrl+C.
- Fixed reused unnamed Native Agent terminals retaining aliases, exported variables, PATH changes, directory changes, or `exit` effects across unrelated commands. Unnamed commands now run in isolated shell scopes while named and explicitly targeted terminals preserve intentional persistent state and leave the unnamed pool once targeted. Prompt-watchdog termination interrupts only the active command, preserving and correctly finalizing the persistent shell. `execute_command` also returns actionable `native_shell_startup_timeout`, direct-pnpm `pnpm_store_mismatch`, and direct-Node/undici `managed_network_proxy_unaware_dns` guidance without automatic replay, configuration pinning, or destructive dependency cleanup.
- Fixed `apply_diff` ambiguity around literal Git conflict and tool-marker lines. The advertised SEARCH/DIVIDER/REPLACE grammar is now shared across tool metadata and schema guidance; bare `=======` remains literal payload in DIVIDER mode, standalone tool-marker payload lines have a documented unified-diff `@@` path, and malformed blocks report their positional index, exact line, violated marker rule, and recovery guidance.
- Fixed background review capture failing on large binary changes or excluded large diffs. Git review scopes now omit binary patch payloads, retain bounded binary-change metadata, and apply `excludePaths` before Git output is buffered. Automatic ACP default/review routes now fall back transparently to native when images require native handoff, while explicit ACP requests still reject unsupported images. OpenAI-compatible streams that close before any provider event now use the existing bounded stream-reconnect budget instead of failing immediately.
- Fixed terminal control sequences and lone carriage-return redraws leaking into cleaned `execute_command` output, which could make nominally machine-readable CLI output such as JSON unparsable. Cleaned output now uses complete ECMA-48 control-sequence matching and final-redraw semantics while preserving terminal-renderable controls in `terminal_raw_output`. The foreground interactive-prompt watchdog now recognizes `Yes/No/All` choice lists and applies equally to sandbox and Native Agent commands; background commands remain observation-only.
- Fixed sandbox commands becoming unusable after development tools left symlinks, hard links, or unsupported nodes inside protected Git metadata. Protection remains fail-closed, but `execute_command` now returns bounded `sandbox_structural_protection` recovery guidance with the protected or unexpected path and node kind instead of a bare launch failure. Invalid root instruction aliases are ignored consistently by instruction loading and sandbox protection, surfaced as sandbox metadata warnings, and no longer block unrelated commands.
- Fixed built-in agents sometimes ending an otherwise complete turn without calling `set_task_status`, leaving the response without final-status styling or a structured result. On a natural prose-only stop with no unfinished todos or queued user message, AgentLink now sends one private reminder to set the truthful final status without repeating completed work; if the reminder is ignored, the turn remains honestly unmarked rather than synthesizing completion.
- Fixed reviewed file edits trusting stale or non-file editor buffers after interrupted sessions. Saves now require canonical document/target identity, hash freshly read disk bytes, and report whether a dirty buffer already contains the proposed content. `write_file` and `apply_diff` now support `save_without_formatting` for exact preservation, and valid YAML/JSON corrupted by a save participant is restored without formatting or fails closed.
- Fixed protected Git metadata recovery gaps. `git merge-tree --write-tree` is recognized before launch, and sandbox-denied Git/libgit2 writes receive bounded `protected_git_metadata` guidance only when the denial is tied to the repository's protected marker.
- Expanded fail-closed read-only command recognition for safe Git plumbing reads and narrow `mise` help forms. Rejections now return stable `readonly_policy_rejected` recovery data instead of a bare failure.
- Fixed short sandbox commands intermittently failing with macOS `E2BIG` and leaving unusable channels. Sandbox environments now preserve explicit values while deterministically bounding inherited entries, preflight the final argv/environment before spawn, return value-free `sandbox_environment_too_large` diagnostics, and retire the failed channel.
- Fixed OAuth-capable MCP servers opening repeated browser login tabs across project hubs and VS Code windows when token refresh or config reloads overlapped. AgentLink now coordinates one active authorization flow per server across windows, retains known-server state across hub generations, retries silently when another window refreshed shared credentials, keeps explicit Reauthenticate available after the active flow, and adds privacy-bounded local diagnostics through `npm run telemetry:mcp-auth`.
- Fixed OpenAI-compatible models sometimes printing XML-style tool-call blocks into the assistant response instead of executing them. AgentLink now recovers complete fallback calls for tools offered on that exact request, while unknown, malformed, or incomplete markup remains visible and is never executed or silently dropped.
- Fixed a reload wedge in multi-tab chat: a tab whose bound session was never persisted (an empty New Chat at reload time) or whose session record disappeared from disk would stay stuck on "Checking model setup" after switching to it, with sending blocked. Selecting such a tab now publishes a usable New Chat composer state, and a tab pointing at a missing session record is unbound and revived instead of rejected.
- Fixed `write_file` and `apply_diff` reporting accepted edits that did not survive save or diverged between the editor and disk. Accepted writes now include verified exact/transformed durability evidence and a final-content hash; reverted, divergent, missing, unreadable, and exact-preservation failures return canonical errors. Known Unity serialization files use VS Code's Save without Formatting path, and transformed `apply_diff` blocks no longer claim stale applied ranges.
- Fixed sandbox commands failing before launch with `posix_spawn failed: Argument list too long` in repositories with large protected skill, rule, or instruction trees. Sandbox runtime helpers now canonicalize the compact filesystem write-denial roots and keep integrity snapshots separate instead of redundantly expanding every protected file into the macOS `sandbox-exec` argument.
- Fixed read-only tools asking for outside-workspace path permission before reading exact agent instruction artifacts such as `AGENTS.md`, `CLAUDE.md`, and `SKILL.md`. These files now remain directly readable with or without Approve for Me, including through `get_context` and non-interactive child execution, while writes, sibling memory/rule/config files, environment secrets, credential stores, and authenticated CLI configuration retain their existing approval protections.
- Fixed a VS Code chat webview crash ("Agent render error: Cannot read properties of undefined (reading 'sessionId')") triggered by any composer-posted message — such as `@`-mentioning a file — while the focused tab had no session yet. The message-addressing fallback treated a tab's legitimate null session id as missing and dereferenced an absent pinned-pane address.
- Fixed the browser transcript briefly flashing the previous conversation (with the new message appended to it) after starting a new Ask Agent chat. Full owner checkpoints published mid-stream by the relay data plane — emitted on session switches and state rebases — reused the previous event's sequence number, so relay consumers discarded them as duplicates and applied subsequent incremental events onto stale state. Published checkpoints now claim a fresh sequence; this also fixes a recovery-resync dead-end where a repair checkpoint at an unchanged sequence was ignored by the diverged client requesting it, and applies to VS Code workspace tabs mirrored over the relay as well.
- Fixed the browser Ask Agent ending turns claiming work it never delivered (for example "Prepared a meeting guide…" with no guide in the chat). Completing a turn via `set_task_status` with no visible response — no assistant text and a summary that is empty, a teaser ("Here is the plan"), or a past-tense recap — is now bounced back to the model once with instructions to write the actual answer, matching the VS Code agent's summary contract; the Ask Agent tool description and system prompts now state that tool results and status summaries are not visible deliverables.
- Fixed browser Ask Agent "New Chat" losing the new session so the next message landed at the end of the previous conversation. New chats are now targeted by a browser-minted session id the moment the button is clicked (clicks no longer no-op while an earlier request is still in flight), a freshly created empty session now survives helper restarts instead of silently falling back to the previous session, and a send addressed to a session the helper no longer knows re-creates that session rather than appending to whichever session happened to be active. New-session and session-load requests are now logged for diagnosability.
- Fixed premature "terminal pool exhausted" failures in the implicit agent terminal pool. Background commands — including foreground commands that time out or are handed to background — now release their foreground pool slot while running and count against a separate, larger background limit; commands that arrive while the pool is busy wait for a slot instead of failing immediately (fixing a race that reported exhaustion while every terminal was idle); channels rejoin the pool when their background command finishes; and the exhaustion error now names only the actually busy terminals with their running commands instead of blaming every terminal.
- Fixed slow AgentLink terminal rendering during sustained heavy output. PTY and sandbox output is now coalesced for a few milliseconds before parsing and delivery (mirroring VS Code's pty-host data buffering), and the terminal webview writes each run of output to xterm in one call, cutting per-chunk postMessage/acknowledgment round trips and eliminating forced replay resyncs caused by render-queue batch overflow.
- Default new installations to flagship GPT-5.6 Sol while keeping the Pro-only GPT-5.3 Codex Spark model available.
- Migrate persisted selections only after their model is retired, including the former GPT-5.3 Codex default, before session creation, restore, mode switches, or manual model updates.
- Report an unavailable selected model directly instead of misdiagnosing it as unavailable native web search during request preflight.
