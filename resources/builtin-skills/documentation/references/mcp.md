# Configuring MCP Servers in AgentLink

This is the owning guide for configuring and using MCP servers. See [Tools](tools.md) for agent-facing MCP tool families and the [complete reference](complete-reference.md#connect-the-built-in-agent-to-mcp-servers) for compatibility detail.

## UI entry points

- `/mcp` — open the shared MCP Manager (connection status, tools/resources/prompts counts)
- `/mcp-config` — configuration-oriented view (guided setup, JSON import, sources)
- `/mcp-refresh` — explicitly reconnect configured servers (ordinary catalog changes load automatically)

The MCP Manager has four views: **Overview** (config + status + enabled/disabled state), **Sources** (each layered file in precedence order, with read health and editability), **Guided setup** (stdio, HTTP, legacy SSE), and **Import JSON** (paste one or many servers; conflicts require explicit Skip/Replace/Rename). A multi-project workspace uses one Manager with a project selector. The Manager in both sidebar and editor chat panes updates after MCP config file changes. **Connect** starts an enabled server shown as "Configured · not connected" and may open sign-in. **Refresh** retries connections for the selected project and can initiate sign-in for configured servers without a runtime entry; **Reconnect** retries a server already in the runtime without forcing sign-in; **Reauthenticate** starts a fresh OAuth flow. Enable/disable changes remain configuration mutations. Actions return updated status to the pane where they were requested.

### Desktop MCP window

In standalone Desktop, **More → MCP** and the **MCP Servers…** app-menu item open a separate, resizable manager window. `/mcp`, `/mcp-config`, and `/mcp-refresh` open that same window rather than a panel beside the composer. Reopening focuses the existing window; closing it does not disconnect servers.

The window uses the same server-management controls as VS Code: add/edit, import JSON, remove, enable/disable, connection recovery, environment/header configuration, and native raw-config opening. It shows live connection state and tool/resource/prompt counts. **Refresh** retries quietly. **Connect** and **Reconnect** recover one configured server without clearing its credentials; **Reauthenticate** starts a fresh remote OAuth sign-in. When first use or an explicit Connect/Reconnect/Reauthenticate action needs sign-in, Desktop opens the system browser directly without an extra confirmation card. Complete or decline sign-in on the provider's page. Closing the browser tab does not immediately cancel the pending connection; use **Cancel** in the manager to stop it, or let it time out. Closing the window cancels its manual sign-in, not an unrelated agent turn. Completed and cancelled operation banners can be dismissed and clear automatically after five seconds; failures remain visible until dismissed. Manual connection actions are unavailable during an active turn; an outstanding manual action must finish or be cancelled before an agent turn can start.

Desktop MCP tool approval offers **This Tool** or **Whole MCP**, with **Session** or **Global** rule scopes. Project controls are hidden because Desktop is projectless. **Session** applies only to the current conversation. **Global** writes the shared `~/.agentlink/mcp.json`: a tool rule adds to `allowedTools`, while a whole-server rule sets `toolPolicy: "allow"`. Desktop and VS Code both load these rules on later connections/turns, including after restart; more-specific project settings can override them. If an existing Ask Agent policy would hide the saved approval, Desktop updates that policy too. Existing connection fields and credentials are preserved. Shared Global approval requires a server connection defined in the global sources; for a server defined only in the Ask Agent profile, use Session or configure a shared global definition first. A failed save leaves the approval open and does not allow the tool. Shared Global rules must be saved from native Desktop or a loopback client, not a LAN browser session.

Desktop uses the projectless Ask Agent profile. Structured server edits are saved to `~/.agentlink/ask-agent/mcp.json`; inherited global definitions remain unchanged except when explicitly saving a shared Global approval rule. **Inherited** is a source label, not an error, and **HTTP** is a transport label. Editing or disabling an inherited server creates an override. Fields omitted from that override, including existing headers/environment values, remain inherited. Removing an override reveals the inherited definition again. Configuration stays saved if reconnection fails. Raw config opening uses the Desktop's native bridge, not a browser-remote endpoint.

Native Desktop MCP connections follow VS Code's HTTP(S) networking, including localhost, private LAN, Tailscale, and private identity providers. Desktop does not add a public-network-only OAuth filter. TLS verification, first-use sign-in gating, callback state validation, cancellation, and isolated credential storage still apply. MCP tool-call approvals are unchanged. Browser-remote secret/local-process restrictions remain separate.

Desktop's native HTTP/SSE connections can refresh tokens silently while idle. Browser-owning `mcp-remote` proxies are started or relaunched in the background only when their cache has a usable, unexpired access token; otherwise they wait for targeted use or an explicit connection action. This avoids treating a refresh token alone as proof that a proxy will stay noninteractive. A proxy with a revoked but unexpired token, or another local process that opens its own browser, is outside AgentLink's native OAuth browser gate.

## Config files and precedence

For each project, server definitions merge from these files in ascending priority (later overrides earlier for the same server name):

1. `~/.agents/mcp.json`
2. `~/.claude/mcp.json`
3. `~/.agentlink/mcp.json`
4. `<workspace>/.agents/mcp.json`
5. `<workspace>/.claude/mcp.json`
6. `<workspace>/.agentlink/mcp.json`

AgentLink writes structured changes only to `.agentlink/mcp.json` sources (project or global). To change an inherited `.agents`/`.claude` server, create an AgentLink-owned override instead of editing those files. Projectless Ask Agent loads global compatibility sources followed by `~/.agentlink/ask-agent/mcp.json`; the standalone Desktop preview uses this same configuration without requiring VS Code. On macOS, Desktop starts its helper with the login shell's `PATH` so global stdio servers using commands such as `npx` can resolve even when the app is launched from Finder. If shell startup fails, it keeps the inherited `PATH`; an unavailable executable is omitted from the Desktop turn rather than failing the question. Restart Desktop after changing your shell's executable paths.

The main agent receives the union of every available workspace project's effective servers. Identical definitions are connected once. Different same-name definitions are kept under stable project-qualified runtime names, so one project's MCP config cannot silently hide another's.

## File format

Standard `mcpServers` object:

```json
{
  "mcpServers": {
    "example": {
      "command": "example-mcp-server",
      "args": ["--stdio"],
      "timeout": 300000,
      "toolPolicy": "ask",
      "supportsParallelToolCalls": false,
      "disabled": false
    }
  }
}
```

- HTTP servers use `url` (`serverUrl` is normalized to `url`; `streamable-http` normalizes to `http`).
- JSONC, UTF-8 BOM, and a single complete ```json fence are accepted on import; unknown client-specific fields are reported as **Not imported**, not silently written.
- Prefer `${VAR}` references for secrets in env values and headers — AgentLink expands them at runtime. Values are masked in the UI but stored plaintext in the file. URL userinfo is rejected; don't put credentials in args or query strings.
- `disabled: true` persists across refresh/reload and removes the server's tools from the runtime.
- `timeout` is the per-tool-call inactivity timeout in milliseconds (default: `60000`). AgentLink respects any positive finite configured value; MCP progress notifications reset the inactivity window, and HTTP/SSE transport deadlines do not shorten it. There is no separate hidden total cap: an active server can extend the call by continuing to report progress, while caller cancellation still stops it.
- MCP tools run concurrently only when the tool advertises the read-only annotation, or when the server opts in via `supportsParallelToolCalls: true`.

## MCP from Agent Plugins

Canonical Agent Plugins 1.0.0 may declare `stdio`, Streamable HTTP, and legacy SSE servers. These definitions are immutable package content rather than ordinary `mcp.json` sources: connection details are shown in the Agent Plugin install/update review and cannot be edited in the MCP Manager. AgentLink-owned overlays can disable a plugin server or change its tool policy, allowlist, disclosure, and parallel-call setting without modifying the package.

Plugin servers are scoped to global or one canonical project identity. The requesting project receives its enabled global servers plus its own enabled project servers; another project's plugin server is excluded. A project plugin shadows a global plugin with the same manifest name. Projectless sessions receive no plugin MCP servers. Each server connects independently so one invalid, offline, or authentication-failing entry does not block its siblings.

For `stdio`, `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` are expanded only in arguments, environment values, and `cwd`; command tokens, URLs, and headers are never interpolated. `PLUGIN_ROOT` points at the reviewed immutable package generation. `PLUGIN_DATA` points at persistent AgentLink-owned data that survives updates and ordinary uninstall/reinstall. **The server process runs locally outside AgentLink's command sandbox**, so review its command, arguments, working directory, and environment before enabling the plugin. No dependency or setup hooks run automatically. MCP tool calls still use ordinary discovery and approval policy after connection.

For Streamable HTTP and SSE, configured headers are injected only for the reviewed MCP origin. They are not sent to OAuth endpoints, cross-origin redirects, or cross-origin SSE endpoint events; client- and OAuth-controlled headers take precedence. Plugin transports do not silently fall back to another transport type.

Plugin MCP entries appear read-only in the main MCP Manager and in the Agent Plugin manager. The browser remote may inspect bounded status and policy summaries but cannot mutate plugin state or configuration. Agent Plugin management itself is documented in `references/customization.md`.

## Behavior notes

- Saving and connecting are separate: a valid config stays saved even when the server is offline or needs auth.
- HTTP OAuth is coordinated across project hubs and open VS Code windows. Automatic connection recovery can open at most one authorization flow for a server at a time; other attempts pause with a **Reauthenticate** action instead of opening duplicate browser tabs. A short post-flow cooldown blocks repeated automatic prompts, while an explicit Reauthenticate may bypass the cooldown after any active flow finishes.
- AgentLink continues to use a configured `mcp-remote` command as the MCP transport. A proxy with cached credentials may start in the background so it can refresh silently. A cache-cold proxy waits until an agent first uses that specific server before starting interactive login. Servers that require browser sign-in during a silent connection also wait for first use. Unrelated messages and other MCP servers do not start that login; the agent can find waiting server names with `find_mcp_tools` and request a specific server to discover its tools. Explicit Connect and Reauthenticate actions can still start sign-in immediately. If initial proxy startup fails, AgentLink pauses automatic startup retries instead of repeatedly relaunching the proxy and browser; use **Reconnect** or **Reauthenticate** to try again. A proxy that connected successfully and later drops still reconnects in the background.
- In VS Code-backed MCP connections, disabling or disconnecting a server cancels queued connection attempts and pending OAuth prompts/callbacks, including manual reauthentication. Cancelled work cannot later reopen sign-in or reconnect the server. An unanswered refresh-failure reauthentication prompt expires after 60 seconds; the browser callback retains its five-minute deadline. Use **Reauthenticate** to start a fresh attempt. Already-open browser tabs or VS Code notifications may remain visible, but late responses do not resume the cancelled flow.
- MCP config reloads preserve which servers were already known, so touching an existing config does not reclassify every OAuth server as newly added or trigger interactive authorization. When another window refreshes shared credentials first, the waiting connection retries silently with the newer token generation.
- For local diagnostics, `npm run telemetry:mcp-auth` summarizes bounded MCP auth events from `~/.agentlink/mcp-auth-telemetry.jsonl`, including browser-open bursts, trigger paths, refresh fallbacks, and lease contention. It never records tokens, headers, authorization URLs, callback parameters, or raw SDK errors; server identities are locally salted in telemetry.
- Writes are revision-checked and atomic; concurrent external edits produce a `config_changed` result rather than an overwrite.
- Large catalogs are progressively disclosed (`find_mcp_tools` / `call_mcp_tool`); the same approval model applies to MCP tools as to native ones. MCP runtime names containing characters that provider function APIs reject, or exceeding their portable length limit, are also routed through this bridge, so one incompatible server or tool name cannot invalidate the whole model request.
- A timeout or cancellation leaves remote completion unknown. AgentLink does not automatically retry; check a server-provided status/read operation before repeating a potentially mutating call.
- Browser surfaces backed by VS Code: main-profile browser config is read-only; loopback Browser Ask Agent may configure local-process servers; LAN sessions may configure only secret-free HTTP/SSE servers. Remote browser edits cannot change an existing server's URL or transport while retaining stored/inherited environment or header credentials. Make those changes locally in VS Code or native Desktop. This restriction applies to browser-remote writes, not native Desktop MCP networking.
- Standalone Desktop connects enabled, configured servers quietly at helper startup and retains those connections across turns and conversations. Config changes are reconciled automatically without restarting unchanged connections. Servers needing browser sign-in wait until the agent targets one by name with `find_mcp_tools`, a tool call, resource read, or prompt request; unrelated turns do not open the sign-in browser. Standalone Desktop executes tools pre-authorized by `toolPolicy: "allow"` or `allowedTools`; tools using the default `ask` policy display an MCP approval card with allow-once, current-conversation tool/server rules, and shared Global tool/server rules. Conversation grants are runtime-only and disappear when the helper stops or the conversation is deleted; Global rules persist in the shared MCP configuration. Standalone Desktop also lists and reads configured MCP resources and prompt templates without VS Code. MCP form elicitation uses the same validated activity-shelf controls as the remote browser and cancels with the active turn.
- Desktop only starts a configured `mcp-remote` proxy unattended when its cache has a usable, unexpired access token. An expired token with a refresh token still waits for targeted use or manual connection. This gate also applies to background reconnects. A revoked token that appears unexpired, or an arbitrary local process that opens its own browser, cannot be universally controlled by AgentLink's native first-use OAuth gate.
- The CLI uses the shared per-session MCP runtime to expose `find_mcp_tools` and `call_mcp_tool` for servers awaiting first-use sign-in, plus `list_mcp_resources`, `read_mcp_resource`, `list_mcp_prompts`, and `get_mcp_prompt` alongside connected server tools. Discovering tools without a server name lists servers needing sign-in without connecting them; targeting a server connects only that server, and its tools can be called in the same turn. Resource and prompt reads require a current enabled server definition, but do not prompt for per-call approval. Server form elicitation opens an interactive terminal control, validates submitted fields, and cancels when the operation or turn ends. Multiple calls from the same turn to one server share an elicitation owner. Hub connection status and warnings appear in the CLI status line; `agentlink mcp status` still reports configuration, not live connections. Use `agentlink mcp reauthenticate <server-name> --project <path>` from an interactive terminal to replace the CLI's OAuth credentials for an enabled remote server. It requires typed confirmation and a separate browser-opening confirmation after the OAuth destination passes the public HTTPS check. Existing tokens remain available if the new sign-in is cancelled or fails; successful sign-in replaces them.
- On macOS, standalone Desktop opens the system browser directly when targeted first use or an explicit connection action requires OAuth, without an extra confirmation card. Native Desktop supports the same HTTP(S) MCP and OAuth network destinations as VS Code, including private networks and local development servers; normal SDK/native fetch redirect behaviour applies. The helper receives a state-bound callback on its loopback listener and stores dynamic client registration plus tokens in Keychain without exposing credentials to the Electron renderer or browser client. Silent refresh uses the same native networking as sign-in. Disabled, removed, or changed configurations cannot resume stale sign-in work or save late tokens. The desktop browser callback uses AgentLink's branded page and says **Authorization received / Finishing setup** until the app completes token exchange; it is not itself confirmation that the connection is ready. The helper retains shared MCP connections across conversations; finishing, cancelling, or deleting a conversation releases its action authority without closing other ready connections. Changed, removed, or disabled server definitions retire their affected connections, and helper shutdown closes all transports. URL-mode elicitation remains declined because it is separate from MCP transport OAuth. The native Desktop MCP Manager supports structured configuration changes and raw-config opening; the browser does not gain arbitrary file access. Its **Connect** and **Reconnect** actions recover one configured server with existing credentials, while **Reauthenticate** starts a fresh Desktop OAuth sign-in for an enabled remote server. Existing tokens remain available if the new sign-in is cancelled or fails; successful sign-in replaces them. Manual connection actions are unavailable during an active turn. Non-macOS shared credential adapters remain later parity work. CLI and standalone Desktop use distinct Keychain accounts for MCP OAuth; VS Code uses extension-host credential storage. Existing credentials in the former shared Keychain account are not migrated or deleted, so a new CLI or Desktop login may be needed. Reauthenticating one surface does not change the others.
