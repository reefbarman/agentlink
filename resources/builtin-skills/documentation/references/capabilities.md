# AgentLink Capabilities Overview

AgentLink is a VS Code extension whose built-in agent chats in stable independent tabs, edits files through diff views, runs commands in the integrated terminal, and uses VS Code diagnostics, symbol navigation, code actions, and rename support. Chat tabs can move between the sidebar and restorable editor panels; at least one tab remains docked, closing a popped panel docks it again, and switching presentation does not interrupt another tab's work. Read-only turns can run concurrently; write-capable turns in the same window serialize across the shared workspace mutation domain, except that native background writers delegated an enforced `ownedPaths` scope run alongside the tree writer and only serialize against overlapping delegated scopes and checkpoint operations. AgentLink also connects to MCP servers, spawns background agents, and can be remote-controlled from a browser.

For any per-tool details (parameters, response shape), read the `## Tools` section of the shipped README.

## Modes

| Mode        | Purpose                                                                            |
| ----------- | ---------------------------------------------------------------------------------- |
| `code`      | Primary implementation mode: read, edit, run commands, navigate symbols, MCP tools |
| `architect` | Planning and design with read/search/language tools                                |
| `ask`       | Lightweight Q&A with read/search tools only                                        |
| `debug`     | Investigation with commands, language tools, and search                            |
| `review`    | Focused code review with structured review output                                  |

Switch with `/mode <slug>` or the mode selector. Default mode: `agentlink.defaultMode`. In foreground sessions, mode instructions travel in-conversation (`<current_mode>` blocks) and all modes' tools are advertised for prompt-cache stability across switches; out-of-mode tool calls are rejected at invocation with guidance to `switch_mode`. Projects can add or override modes via `modes.json` (see `references/customization.md`). With no workspace folder open, AgentLink instead starts a non-persistent, Ask-only projectless chat using global model/reasoning/context settings. Self-contained pasted or dropped images/PDFs remain available, but workspace files, path attachments, shell/editor tools, MCP, checkpoints, and approval controls require an open folder.

## Models and providers

- Model picker is built into the chat UI (`/model`). Per-mode defaults: `agentlink.modeModelPreferences`; per-mode thinking level: `agentlink.modeReasoningEffortPreferences`.
- Prompt guidance is selected by model profile. A committed frontier cohort (current Claude Opus/Sonnet and full-size Codex models) automatically uses the compact `reasoning` prompt; unknown, custom, and small-tier models use the full `compatibility` prompt, and `agentlink.modelPromptProfiles` can apply an exact model-ID override either way. Reasoning support or thinking controls alone do not select the compact profile.
- Auth: an empty chat reports the selected model's live setup state and offers direct **Continue with ChatGPT/Codex** OAuth, OpenAI API-key, Anthropic API-key, and OpenAI-compatible setup paths. While setup is needed, provider-bound sends are held without clearing the draft or attachments; local `/new`, `/mode`, `/model`, `/environment`, `/memory`, and `/fleet` controls remain available. Command Palette entries remain available: **AgentLink: Set Anthropic API Key**, **AgentLink: Set OpenAI API Key**, **AgentLink: Sign In to OpenAI/Codex** (ChatGPT/Codex OAuth, multi-account management available), plus secure set/clear commands for named OpenAI-compatible connection keys. “Credentials configured” means ready to try, not verified provider connectivity.
- Anthropic model metadata (context window, output tokens, reasoning efforts) refreshes lazily from the API; toggle with `agentlink.anthropic.dynamicModelCapabilities`.
- **AgentLink: Configure OpenAI-compatible Model** is the guided, add-only setup path. It selects or creates a named credential, performs bounded user-invoked OpenRouter/generic `/models` discovery with manual fallback and editable conservative defaults, then adds one model backed by one connection. Edit/remove and advanced multi-model settings remain in User Settings JSON.
- `agentlink.openaiCompatible.connections` configures multiple named OpenAI Chat Completions-compatible endpoints (for example OpenRouter or no-auth LM Studio/vLLM) and multiple declared models per connection. Each has a stable local selector ID separate from the upstream wire model ID. Per-model `modelFamily` (`anthropic` or `openai`) can select vendor-appropriate prompt behavior for proxy-hosted models without changing endpoint routing or credentials. Text, reasoning, images when declared, tool calls, replay, usage estimates, condensing/helper calls, and Browser Ask Agent share the portable runtime. Chat-only models remain selectable but are excluded from automatic background routing. Browser Ask Agent can use wizard-created models but cannot write configuration or credentials.
- The local OpenAI-compatible helper settings (`agentlink.openaiCompatible.baseUrl`, `.model`, `.apiKey`, `.timeoutMs`) configure question detection and background-agent status summaries separately from chat connections.
- **Polish prompt** — sparkle button in the composer toolbar rewrites the draft (spelling, grammar, wording) with the current provider's fast model before sending; a revert button restores the original text. Available in VS Code chat and the browser remote; uses model quota. See the README "Core built-in agent features" section.

## Built-in slash commands

`/new`, `/mode`, `/model`, `/condense`, `/handoff`, `/context-doctor`, `/environment`, `/workspace`, `/checkpoint`, `/revert`, `/help`, `/fleet`, `/remember`, `/memory`, `/skills`, `/plugin`, `/plugins`, `/mcp`, `/mcp-config`, `/mcp-refresh`, `/btw`, `/worktree`, `/pair`, `/usage`. Custom commands and detected skills appear in the same picker (see `references/customization.md`). Type `/` to filter by any part of a command name; exact and prefix matches rank before substring matches. The picker expands upward from the input so the draft remains visible. Use Up/Down (or Home/End) to choose a result, Enter to select it, Tab to complete it, and Escape to close the picker.

- `/handoff` — prepare an editable, bounded continuity brief from the current idle workspace session. Review the brief, then start a durable fresh successor session that links back to its predecessor without transferring approval authority. The successor can use `scope: "handoff_source"` transcript recall for its direct predecessor only. Available in VS Code chat and browser workspace tabs; Browser Ask Agent and projectless chats do not support it.
- `/context-doctor` — append a read-only workspace-session report covering prompt/tool/context-ledger allocations, retained and repeated tool results, condensation evidence, and explicit unavailable diagnostics. It makes no model request, and the report is excluded from future provider and condensation context. Available in VS Code chat and the browser remote, but not projectless Browser Ask Agent.
- `/environment` — open the current workspace session's runtime environment, loaded instructions, and system prompt in the Chat Activity Shelf without a model request. Available in VS Code chat and browser workspace tabs, but not projectless Browser Ask Agent.
- `/workspace` — show the exact active AgentLink history directory, workspace identity, and legacy namespace or v2 lineage in the VS Code output channel. It is a diagnostics/recovery command, not a VS Code workspace switcher, and is unavailable in the browser remote because migration remains VS Code-only.
- `/memory` — open the local autonomous-memory manager without a model request. Inspect/filter records, provenance, revisions, and audit history; forget/restore, undo, clear a confirmed scope, or import/export versioned archives. VS Code supports global and current-project scopes; projectless Browser Ask Agent supports global scope only.
- `/plugin <install|install-declared|list|enable|disable|update|uninstall|purge> [source|name|install-id]` — review-gated Agent Plugins 1.0.0 management on macOS/Linux. Install accepts Git remotes, HTTP(S) archives, file URLs, directories, `plugin.json`, ZIPs, and TAR-family archives; see `references/customization.md`. `/plugins` lists global, project, and declared entries. Mutation is VS Code-only; browser remote provides a bounded read-only manager. Projectless sessions and Windows load no plugin components.
- `/btw <question>` — quick side question in a forked read-only session; answer can be promoted into the main transcript. VS Code-only.
- `/worktree [task] [--branch <name>]` — set up isolated work without interrupting the current turn; missing details are gathered in a small text session, followed by inline **Create & start** / **Create & prefill** actions in the Activity Shelf. VS Code-only.
- `/pair` — pairing code for a new browser remote device.
- `/usage` — Codex subscription usage and reset times.

## Context management

- Native tools use stable progressive disclosure: essential definitions remain inline, while eligible tools are discovered through `find_native_tools` and invoked through `call_native_tool`. Discovery is bounded and searches only the immutable catalog already authorized for that provider request; multiple exact tool names are returned first in authorized catalog order, then remaining conceptual terms add deterministic relevance-ranked OR matches. Queries without useful terms fall back to the authorized catalog instead of reporting no tools. Discovery cannot broaden mode, profile, skill, background, web, or surface restrictions. Live activity and public transcripts show the canonical target, while provider-private replay retains the wrapper identity and tool-call ID.
- Every provider request receives an immutable model-aware context ledger: model input/output envelope, output reservation, safety buffer, required layers, bounded retrieved/working-set allocations, omissions, remaining capacity, and overflow. Required layers are measured rather than silently reduced, so overflow can still be reported.
- `get_context` unchanged-content omission is opt-in, current-session, and exact-range-only; `refresh` forces content back in. Context Health separately reports memory, lexical/vector/structural retrieval, and index health: in VS Code it is in the sidebar Activity section between Tool Calls and Codebase Index, while the Browser Gateway keeps it in the Chat Activity Shelf. `/context-doctor` reports measured request allocation/retention evidence, not retrieval-store health or memory conflicts.
- Browser Ask Agent applies the same mechanism to a stricter helper-owned projectless catalog. It can defer only already-authorized global-memory and display-safe image tools; it cannot discover or invoke file writes, shell commands, VS Code editor/language state, semantic code search, repo maps, or background/fleet orchestration.
- **Auto-condense** compresses the conversation when the context window fills (`agentlink.autoCondense`, per-model thresholds in `agentlink.modelCondenseThresholds`) and deterministically reattaches the current structured TODO list with its completed, in-progress, and pending states. Resume guidance tells the agent to reconcile stale status against the checkpoint/workspace rather than repeat already-completed work; `/condense` triggers it manually, while `/context-doctor` inspects the latest completed allocation without changing it.
- **Checkpoints** (`/checkpoint`, `/revert`) snapshot the workspace into AgentLink's own shadow git repo under `.agentlink/checkpoints/` — separate from the project's real git history.
- Sessions persist and restore across VS Code reloads. `/handoff` creates a separate, explicit fresh-session lineage: its reviewed brief and predecessor identity are durable, while the old session stays unchanged and approval authority does not transfer. The successor may recall only that direct predecessor through the bounded `handoff_source` transcript-recall scope. For local workspace folder additions, AgentLink can offer to branch-copy the prior history into a new active lineage, start fresh, or defer. Source history stays unchanged. Automatic migration never runs for a reverse folder-removal transition or into a destination that already has history; those cases need an explicit recovery flow rather than selecting a branch automatically. The visible migration notification waits for active sessions to become idle, then reports inspection/copy/publication/reload stages rather than retargeting a running runtime in place.

## Autonomous memory

- `agentlink.memory.mode = autonomous` enables typed, audited low-authority memory and is the default; set it explicitly to `off` to opt out. Memory is evidence only and cannot authorize tools or override current user, repository, instruction, skill, or command evidence.
- `manage_memory` performs provenance-bearing, secret-scanned, quota-bound CRUD and undo without a per-write approval card. `recall_memory` provides bounded credential-free lexical retrieval. When autonomous memory is enabled, normal foreground sends, retries, interrupted-session resumes, and native background invocations also receive one bounded immutable low-authority recall snapshot that is reused across provider retries/tool loops without entering transcript history.
- Legacy global and project `.agentlink/memory.md` files are imported idempotently into typed records and left byte-identical for rollback; they are no longer concatenated into the system prompt. `propose_memory` remains the reviewed path for authoritative instructions, skills, and commands; it no longer writes low-authority memory.
- `/memory` provides direct inspection and lifecycle controls without a model request: bounded search/filtering, record detail, provenance/revisions/audit history, forget/restore, undo, confirmed scope clearing, and versioned JSON import/export. VS Code supports global and current-project scopes. Projectless Browser Ask Agent uses global scope and shares the helper-owned runtime selected unanimously by connected external owners.

## Approvals

Command, write, rename, MCP, and mode-switch approvals render inline in chat, with a separate approval panel for focused review. Key knobs:

- `agentlink.commandAutoApproveTier` — auto-approve terminal commands at or below a safety tier (default `safe`).
- `agentlink.writeRules` — glob patterns always auto-approved for writes.
- `agentlink.recentApprovalTtl` — repeat identical commands auto-approve within the same session and a bounded window when command, canonical cwd, project, execution authority, permission intent, and applicable rule policy still match.
- `agentlink.masterBypass` — skip ordinary command and file-write prompts; native escalation, outside-path reads, MCP tools, protected paths, and read-only/delegation boundaries still apply.
- Exact agent instruction artifacts named `AGENT.md`, `AGENTS.md`, `AGENTS.local.md`, `CLAUDE.md`, or `SKILL.md` are directly readable outside the workspace in either approval mode. The exemption is read-only and filename-specific: writes and sibling memory, rule, command, environment, credential-store, and authenticated CLI configuration files keep their existing protections.
- `generate_image` offers **Generate for Session** on its quota/billing approval card. Selecting it auto-approves later image generations only in that live chat session for the current extension runtime and does not grant unrelated file-write authority.
- **Approve for Me** selects sandbox-first execution with a separate Guardian reviewer and enables session-scoped writes. While its complete policy is active, `write_file` and `apply_diff` can write beneath the operating system's canonical temporary roots (including the per-user temp root and `/tmp` aliases on macOS) without a separate outside-workspace approval; manual modes still prompt, and protected instruction/memory files, `.env*`, credential stores, authenticated CLI configuration, unresolved paths, and symlink escapes remain human-reviewed. With it off, default commands use the native terminal and the ordinary command-card/rule flow. Sequential unnamed native commands isolate aliases, exports, PATH changes, `cd`, and `exit` even when an idle logical terminal is reused; named or explicitly targeted terminals retain intentional persistent-shell state and leave the unnamed pool once explicitly targeted. Foreground prompt termination interrupts only the active command and preserves that shell. Turning session writes back to Prompt disables Approve for Me. While Approve for Me remains active, both settings survive mode switches; session writes selected without it reset to Prompt on a mode switch. Reloading may restore an existing session's valid policy, but a new chat starts with Approve for Me off and no inherited session authority. Routine baseline commands and recognized routine development commands (read-only inspections, version checks, build/test/lint toolchain runs, workspace-bounded file operations, and repo-local `git add`/`git commit`) run without a model call; dangerous commands and requests for listener binding, managed public network, native host authority, supported outside-workspace reads/single-file writes, and fully enumerable `find_and_replace` proposals that reach outside the workspace receive an exact allow/deny review. Command reviews include host-measured filesystem evidence — bounded contents of workspace/temp script files the command would execute (metadata only elsewhere) and location/type/size/entry facts for `rm`/`rmdir` targets — so wrapper scripts are judged by their body and bounded deletes of generated artifacts can be allowed on their merits. Under Approve for Me, `switch_mode` normally changes modes immediately without Guardian or user approval. One deliberate exception preserves the meaning of starting a foreground session in Architect mode: its first exit from Architect requires explicit human approval of the plan, preferably through an `ask_user` option whose `modeSwitch` mapping approves the plan and changes mode in one action. Rejection keeps the gate pending, and the state survives reload. After that first approved exit, later changes to or from Architect are automatic. Sessions that start elsewhere and later enter Architect, plus background Architect sessions, are never gated. The agent still asks questions whenever it genuinely needs user input. Multi-file write grants bind the current session and policy plus the complete canonical affected-file set and every file's full baseline/proposed content, then are consumed once for that complete proposal under all target locks. Canonical or sensitive-path rejection, dirty documents, incomplete or over-limit evidence, and action drift fall back to human approval. Guardian cannot persist path/write/project/global trust, and one-shot authority never transfers to another action or child agent. Arbitrary `rename_symbol` edits stay human-reviewed when per-target authority is missing because VS Code's public edit entries cannot prove that no hidden resource operations exist; outside rename targets cannot inherit blanket session/project/global write approval. Editor application and authorization cover the accepted edit as a unit, while later disk-save failures are reported separately.
- Command rules use one decision model in manual and **Approve for Me** modes. `allow` authorizes a matching invocation without another command approval card, including its requested Protected Terminal, additional capabilities, managed-network route, native route, environment values, and inline payloads; `prompt` always asks, and `forbidden` rejects. Command rules do not bypass the exact approval required for an unseen public destination or the mandatory human card for a native replay after a sandbox process already launched. That recovery card carries first-attempt evidence and keeps normal rule controls for future ordinary invocations, but saved rules never skip the recovery confirmation. Stricter matching rules take precedence. Exact, prefix, and regex are only match strategies. Legacy command rules with no stored decision are interpreted as `allow`. Every safely parsed, wrapper-expanded compound-command segment must be allowed. Validation, protected paths/metadata, read-only/delegation boundaries, and policy/action drift still stop execution. Broad shell/interpreter/wrapper prefixes are not suggested automatically; manual creation remains possible but is warning- and confirmation-gated.
- When no rule covers a command, Guardian cannot authorize it, or the Guardian-denial circuit interrupts automatic review, Approve for Me falls back to the ordinary command card with the same editable command, **Run**, session/project/global rule, rejection, and follow-up controls as manual mode. Guardian or guardrail evidence stays in a collapsed **Why this reached you** section. New rules default to **Allow**; users do not choose between separate sandbox and native rule types.
- With Approve for Me, sandbox routes allow loopback client connections and route public traffic through AgentLink's attributed proxy; private/local destinations remain blocked, while every unseen public destination pauses for exact human approval before the numeric dial, including redirects and later sockets. Direct Node/undici fetch failures with ENOTFOUND/EAI_AGAIN receive proxy-aware recovery guidance; direct pnpm store mismatches expose bounded canonical store paths as evidence for an explicit non-destructive resolution choice. `execute_command.sandbox_permissions` accepts `use_default`, `with_additional_permissions`, `require_managed_network`, or `require_escalated`. Pair `with_additional_permissions` with `additional_permissions.network.allow_local_binding: true` and a reason to start a listener while retaining mediated public networking; a complete matching Allow rule authorizes the listener capability. `require_managed_network` explicitly requests that mediated sandbox networking. Encrypted paths/payloads/credentials remain unknown. Additional network/listener capability grants are created only after approval and other pre-launch checks, immediately before the sandbox runtime starts. If activation fails, `execute_command` reports that the command was not launched and provides same-command retry guidance rather than falling back to native execution. Sandbox launch environments are provenance-aware and size-bounded: oversized host-inherited entries are dropped deterministically, explicit/reserved values remain protected, and an oversized final argv/environment fails before process launch with `sandbox_environment_too_large`, safe contributor names/sizes, and no values. The failed channel is retired rather than reused. The internal `AGENTLINK_SANDBOX_CAPABILITY_GRANT_TIMING=preparation` extension-host environment override temporarily restores the legacy preparation-time lifecycle after a window reload for emergency rollback. With Approve for Me off, default commands use the native terminal; `require_escalated` also requests native host execution under the normal command-rule decision model. Boundary requests require a reason.
- Session approvals can be cleared and command policies added via command palette entries. The approval card and rule editor expose **Allow**, **Prompt**, and **Forbidden** with session/project/global scopes. The command-palette and Trusted Commands creation flow adds Project or Global **Allow** rules, which can then be edited. Session rules and MCP/tool grants are isolated per live chat for the current extension runtime and do not return after an extension-host reload. Restoring a chat whose persisted command mode is **Approve for Me** may recreate fresh session write authority; it does not restore arbitrary session grants.
- Project/global command, path, write, and MCP choices fail closed with an explicit error when the backing config file cannot be updated.
- `diagnose_activity` lets the agent inspect bounded, redacted evidence for recent tool results, warnings, errors, and recorded authorization provenance in its own session. Use `search_session_history` alongside it when exact historical transcript context is needed.

Accepted write results identify whether authority came from master bypass, the architect-plan exception, the Approve-for-Me temporary-directory exception, a session/project/global blanket approval, a workspace setting, a matching write rule, a one-shot Guardian review, or an interactive human decision. `apply_diff` advertises one canonical SEARCH/DIVIDER/REPLACE grammar across its tool description and input schema. In DIVIDER mode, bare `=======` lines are literal payload for ordinary conflict hunks; standalone payload lines whose trimmed text equals a tool marker or the reserved `<<<<<<< SEARCH>` compatibility spelling use unified-diff `@@` input. Malformed blocks report positional index, exact line, stable reason, violated marker rule, and recovery guidance. After saving a single-file `write_file` or `apply_diff` edit, AgentLink verifies the canonical file-backed document and hashes freshly read disk bytes before reporting acceptance. Exact and ordinary transformed saves include durability evidence and a final-content hash; reverted, divergent, missing, unreadable, and exact-preservation failures return errors instead. Both tools accept `save_without_formatting: true` to require exact preservation without ordinary save participants; known Unity serialization files use that path automatically. When an ordinary save participant makes previously valid YAML or JSON unparseable, AgentLink restores the approved content through Save without Formatting or fails closed. Dirty-buffer conflicts state whether an interrupted proposal is already present, and transformed `apply_diff` blocks omit stale positional claims. Post-save failures remain inspectable and are not automatically rolled back. Guardian outside-file review never creates a rule. Protected instruction/memory files, `.env*`, `.ssh`, `.aws`, `.gnupg`, authenticated CLI configuration, unresolved/ambiguous paths, dirty documents, incomplete or over-limit write evidence, and drift stay human-only. Diagnostic evidence is bounded and can report truncation; missing evidence is not proof that an operation did not occur.

## Background agents and orchestration

The agent can spawn parallel background agents for review/research (`spawn_background_agent` and related status/steer/kill tools). Immutable Git review captures omit binary patch payloads, preserve bounded binary-change metadata, and apply excluded paths before buffering. `agentlink.background.maxConcurrent` caps concurrency; `agentlink.background.defaultAgent` picks the general backend (`native:auto` or a configured ACP stdio agent from `agentlink.background.acpAgents`). Image-bearing spawns fall back from automatically selected ACP routes to native; explicit ACP provider requests remain authoritative and reject images. `agentlink.background.reviewAgent` can replace only the opposite-provider side of adversarial `review_*` tasks with a provider-tagged ACP agent; matching foreground providers retain native cross-provider review routing. The machine-scoped `agentlink.background.reviewTarget` selects the `review_*` backend as a provider map whose entries are `{ target, effort? }`: target is `native:auto`, `acp:<id>`, or `model:<local-model-id>`, with an optional `default`. A model target is deterministic (used even on the same provider) and both it and any effort are validated before launch instead of silently falling back; ACP targets control their own effort. Review mode routes review work to background agents. Agents cannot launch worktrees; isolated worktree windows are available only through the user-controlled `/worktree` VS Code flow.

Native background-agent questions go first to the root foreground coordinator. It answers from the existing task, delegation, and workspace context with `respond_to_background_question`; if the answer genuinely needs human judgment or human-only information, the coordinator escalates through its own `ask_user`. Under Approve for Me, eligible native background command, outside-path read, and in-workspace file-write approvals use the same coordinator-first handoff. The coordinator may approve or reject only that exact operation once, or escalate it to the original standard approval card. Mediation does not create a pending human approval, show a card, or trigger status-bar attention; those begin only after escalation. Manual mode, human-only targets, specialized/quota write approvals, outside-write fallback, detached agents, and sessions without an available coordinator use the direct human approval/question flow. The fleet reports `awaiting_coordinator` while a coordinator handoff is pending.

The Agent Fleet panel remains visible while agents are running or paused, then hides after every agent finishes. `/fleet` reveals the completed fleet again in both VS Code and the browser remote. Background result cards distinguish completed, incomplete, failed, and cancelled outcomes. Valid structured findings recovered from ACP output remain successful results; genuine non-success preserves the terminal reason and any partial output. The browser relay carries the richer result state when its shared helper advertises support and otherwise falls back to the legacy coarse status.

Native background children inherit the parent's effective command mode and session-scoped write, path, command, network, and MCP approvals. Later parent mode changes and grants flow to active descendants in that tab's agent tree, while child-only grants and prior inherited authority remain isolated. Review and read-only research children can run beside a foreground writer; their MCP surface is restricted to tools whose servers explicitly set `readOnlyHint: true`, and unannotated MCP tools are unavailable. Read-only ACP children may run classifier-approved non-mutating Claude-style Bash commands inside the workspace; unsafe, ambiguous, background, external-path, and unrecognized execution requests fail closed without approval UI. Writable ACP children receive the session snapshot and can reuse write/path authority for requests with complete structured file locations. ACP read/search requests with a determinable filesystem target follow the built-in path-access policy: workspace and trusted paths approve automatically, and untrusted outside paths go through the outside-read Guardian and then the standard path-access card, whose saved trust rules persist. Opaque provider-defined command requests and tool requests with no determinable target still prompt, on an "External Agent Tool" card labeled with the ACP agent and tool. Recent human command approvals and queued path approvals remain session-bound, and Guardian one-shot authority never transfers.

Inherited authority does not weaken write safeguards: outside-workspace targets, including symlinks resolving outside, still require a matching file rule, and protected instruction or memory files still require explicit approval.

Read-only execution recognizes conservative local Git inspection commands including `merge-base`, `ls-tree`, and `for-each-ref`, plus narrow top-level `mise` help forms. Rejected ambiguous, mutating, networked, or unrecognized requests return a stable `readonly_policy_rejected` payload with actionable alternatives; network reads still require a writable foreground session with the normal approval flow.

## Browser remote control

A local gateway serves a browser UI that mirrors sessions, approvals, questions, background activity, selected-model setup status, fresh-session handoff review, and read-only diff review — one stable URL (`agentlink.browserGatewayPort`) covers all open VS Code windows. Ask Agent stays pinned first, followed by every window's logical tabs rendered directly; tabs from the same workspace stay adjacent and share a tint. Browser selection is client-local and routes by composite `(instanceId, tabId, sessionId)`, so it can control a different live session without changing VS Code focus or layout; docked and popped-out tabs are both reflected. Creating, closing, reordering, docking, and popping logical tabs remain VS Code-only lifecycle controls. The bounded helper-owned relay/event data plane is the dogfood default; `agentlink.browserGateway.dataPlane` can select shadow dual-publication or the complete legacy rollback while semantic parity work continues. LAN access for phones/other devices is opt-in (`agentlink.browserGatewayLanAccess`, mDNS name via `agentlink.browserGatewayMdnsName`) and requires per-device pairing (`/pair`). When a browser workspace chat needs credentials, it directs setup to its owning VS Code window; browser JavaScript never receives credential mutation paths. The browser surface is intentionally read-only for diffs and has no shell or write paths. Browser Ask Agent has its own MCP config source and can use the same configured OpenAI-compatible models; endpoint profiles and credentials stay server-side, owner/generation-bound, and absent from browser snapshots and JavaScript.

## Web access

Native `web_search` / `web_fetch` tools with configurable backends, domain allow/deny lists, and per-turn caps — all under `agentlink.webAccess.*`. See [web access](complete-reference.md#web-access) for cost and privacy notes.

## Semantic codebase search

The default-on `codebase_search` tool is backed by AgentLink's embedded local LanceDB retrieval stores; current production retrieval does not require Qdrant. Each canonical project/workspace-folder root has a reusable store, so windows that reference the same project share its index while unrelated projects do not contend for one global code store. Lexical and structural indexing/search work without credentials. Vector and hybrid ranking require both OpenAI embedding credentials and explicit `agentlink.semanticEmbeddingsEnabled: true`; credentials alone do not send code or search queries to OpenAI. Legacy Qdrant data and code rows from the former global store are not migrated in place—rebuild each project index for the new layout, and expect an older rollback build to need its own Qdrant configuration/rebuild. Settings: `agentlink.semanticSearchEnabled`, `agentlink.semanticEmbeddingsEnabled`, `agentlink.autoIndex`, `agentlink.indexExclusions`, `agentlink.chunkGranularity`. Setup: [semantic codebase search](complete-reference.md#semantic-codebase-search-setup).

## AgentLink Terminal

Sandbox-backed terminals on supported local macOS hosts (`agentlink.terminal.enabled`, `agentlink.terminal.nodePath`). Foreground sandbox commands that end in a high-confidence interactive prompt are terminated after a short inactivity grace and return structured `interactive_prompt` termination evidence without native retry. Background commands remain observation-only and expose prompt hints through `get_terminal_output`. Requirements: [AgentLink Terminal](complete-reference.md#agentlink-terminal).

## Editor entry points

**Add File to Chat**, **Add Selection to Chat**, **Explain with AgentLink**, **Fix with AgentLink** push editor context into the chat without copy/paste.

## Images in chat

Image-returning tools, including MCP screenshot tools, retain previews inside their collapsed tool-call results by default so routine agent inspection does not crowd the transcript. When the user explicitly asks to see an image or screenshot, the agent can call `present_images` to show an existing session image directly in the main transcript without writing a file, consuming generation quota, or requesting approval. The tool can select exact `image_N` IDs or recent images and works in both VS Code chat and Browser Ask Agent. See [present_images](complete-reference.md#present_images) for parameters and response details.
